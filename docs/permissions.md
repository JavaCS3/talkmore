# 权限与隐私

## 按使用方式授权

| 使用方式 | 麦克风 | 输入监控 | 辅助功能 |
| --- | --- | --- | --- |
| `talkmore app` 菜单栏听写 | 需要 | 需要 | 需要 |
| `talkmore record` CLI 录音 | 需要 | 不需要 | 不需要 |
| `talkmore transcribe` 文件转写 | 不需要 | 不需要 | 不需要 |

Talkmore 没有账号登录或云端识别 API Key 配置。默认模型通过公开的 Hugging Face 仓库下载，识别在本机运行。

## 菜单栏首次授权

1. 从终端启动 `uv run talkmore app`，等待菜单栏出现 `TM`。
2. 按 macOS 弹窗提示授权；菜单 `TM` → “授权 / 重新检查权限…” 可以再次发起请求并检查结果。
3. 在系统设置 → 隐私与安全性中，分别检查麦克风、输入监控与辅助功能。
4. 为实际启动 Talkmore 的终端应用或 Python 进程启用权限。当前没有独立的 `.app`，权限归属和显示名称由启动环境决定，未必显示为 Talkmore。
5. 回到菜单重新检查；若仍提示缺失权限，先退出 Talkmore，必要时重启终端，再从原来的启动环境运行。

系统授权只需为自己的启动环境设置；切换终端、Python 安装或虚拟环境后，应再次检查实际权限归属。

## 常见问题

| 现象 | 排查方式 |
| --- | --- |
| `TM !`，提示权限未就绪 | 查看菜单首行缺少哪项权限，到系统设置启用后重新检查 |
| 右 Option 没反应 | 等待模型准备完成；检查三项权限和快捷键设置，确认轻按并松开右 Option，没有其他按键重叠 |
| 模型下载或加载失败 | 查看终端错误与网络状态，随后使用菜单“重试模型加载”；完整缓存或本地目录可离线使用 |
| 录音几乎没有声音 | 检查麦克风权限及系统默认输入设备、输入音量 |
| 文字没有落在原输入框 | 粘贴使用发送时的键盘焦点；录音和转写期间保持目标输入框的光标位置 |
| 提示“已发送粘贴”但目标没有文字 | 目标应用可能不接受系统按键或当前不能粘贴；使用“复制最近结果”后手动 `⌘V` |
| 仍提示权限不足 | 退出并重启 Talkmore 和启动终端，确认授权对象与实际运行环境一致 |

粘贴前最多等待两秒，让物理修饰键松开。超过时间、剪贴板写入失败或按键发送失败时会显示具体错误；不会重试已经发送的粘贴。若剪贴板写入成功，结果会留在剪贴板。

## 权限如何使用

麦克风用于主动触发的录音。输入监控会接收全局按键事件及键码、修饰键状态，用于识别快捷键与取消操作；录入自定义快捷键时读取字符来显示组合键。辅助功能用于全局键盘事件监听及发送完整的 `Command 按下 → V 按下 → V 松开 → Command 松开` 系统按键。

Talkmore 不查询前台应用、输入框或 caret，不遍历辅助功能树，不通过辅助功能写入文本，也不自动切换、激活应用或发送 Enter。录音浮层不能成为 key/main window，忽略鼠标输入；录音与转写流程不会弹出可获取焦点的窗口。授权、快捷键设置窗口应在开始听写前完成操作。

## 数据保存和网络

- 依赖安装和首次模型下载需要网络；音频识别在本机执行，不上传录音。
- 默认模型缓存在仓库 `.models/`，完整缓存通过本地文件清单复用。
- 菜单栏音频与最近结果留在进程内存，不写入录音或转写历史文件；退出进程后不再保留。取消或休眠丢弃当前任务待交付结果，但正在执行的模型推理无法立即中断。
- CLI 的 `--save-audio` 明确保存 WAV，stdout 可以被用户重定向或被运行环境记录。
- 转写文字会写入系统剪贴板，覆盖之前内容，且可能被其他剪贴板工具保存；Talkmore 不控制系统剪贴板的保留周期。
- 快捷键配置写入 `~/Library/Application Support/Talkmore/config.json`，不包含录音或转写文字。

可随时退出 Talkmore，再在系统设置中关闭对应权限。模型缓存与自行保存的录音需由用户另行删除。
